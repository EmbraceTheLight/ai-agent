## 当前核心数据结构

### VectorStore

`VectorStore` 是当前最小内存向量库接口：

```go
type VectorStore interface {
    Add(vector vector, chunk string) error
    Search(queryVector vector, topK int) ([]*CosineSimilarity, error)
}
```

字段含义：

- `Add`：把一个 chunk 文本和它的 embedding 保存到向量库。
- `Search`：输入 query embedding，返回最相似的 topK 个 chunk。

当前 `vector` 还是包内类型：

```go
type vector []float64
```

后续如果要让 `cmd/rag-cli` 或其他包直接构造向量，可以考虑把它导出为 `Vector`。

### Embedding

`Embedding` 表示内存向量库中的一条记录：

```go
type Embedding struct {
    Chunk  string
    vector vector
}
```

当前保存了：

- `Chunk`：原始 chunk 文本，已导出，方便后续 CLI 打印命中内容。
- `vector`：chunk embedding，仍然包内使用。

当前还没有保存 `SourceFile`、`ChunkIndex` 等 metadata。后续拼接引用时，需要把 `Chunk string` 升级成 `*Chunk` 或新增 `SearchResult`。

### CosineSimilarity

`CosineSimilarity` 表示一次命中的检索结果：

```go
type CosineSimilarity struct {
    Embed *Embedding
    Score float64
}
```

字段含义：

- `Embed`：命中的向量库记录。
- `Score`：query vector 与 chunk vector 的余弦相似度。

`Search` 返回结果按 `Score` 降序排列，越靠前表示越相关。

## cosine similarity

当前使用余弦相似度衡量两个向量的语义接近程度。

公式：

```text
cosine(a, b) = dot(a, b) / (|a| * |b|)
```

其中：

```text
dot(a, b) = a1*b1 + a2*b2 + ... + an*bn
|a| = sqrt(a1^2 + a2^2 + ... + an^2)
|b| = sqrt(b1^2 + b2^2 + ... + bn^2)
```

可以这样理解：

- `1`：方向完全一致，语义最相近。
- `0`：方向正交，语义相关性弱。
- `-1`：方向相反。

当前实现会检查：

- 两个向量维度必须一致。
- 向量不能为空。
- 向量不能是零向量。

这些检查很重要，否则可能出现 panic、NaN 或无意义的检索结果。

## topK 实现方式

当前使用小根堆保留 topK 个最高分结果。

核心思路：

```text
遍历所有已存向量
  -> 计算 query 和当前向量的 cosine score
  -> push 到小根堆
  -> 如果堆大小超过 topK, pop 掉当前最低分

遍历结束后, 堆中留下 topK 个最高分结果
```

因为小根堆每次 `Pop` 会先弹出最低分，所以返回结果时需要逆序填充：

```text
ret[topK-1] = 当前最低分
...
ret[0] = 当前最高分
```

这样最终 `ret` 是按相似度降序排列。

## 遇到的问题

### 1. 大根堆和小根堆的方向

一开始容易把堆方向写反。

如果用大根堆，堆顶是最高分。当堆大小超过 topK 时直接 `Pop`，会把最高分弹出去，最后留下低分结果。

因此当前改为小根堆：

```text
堆顶是最低分
超过 topK 时弹出最低分
最终保留 topK 个最高分
```

### 2. topK 返回顺序

小根堆保留的是正确候选，但弹出顺序是从低分到高分。

RAG 检索更自然的返回顺序是：

```text
最高分 -> 次高分 -> ...
```

所以当前在弹出结果时逆序写入返回切片，保证最终结果是降序。

### 3. 向量维度必须一致

query embedding 和 chunk embedding 必须来自同一个 embedding 模型。

如果维度不同，说明它们不在同一个向量空间里，不能直接做 cosine similarity。当前实现会直接返回错误。

### 4. 零向量不能参与 cosine similarity

cosine similarity 的分母是：

```text
|a| * |b|
```

如果任意一个向量长度为 0，就会除以 0，结果没有意义。当前实现会返回错误。

### 5. Search 不应该直接打印

检索函数应该只负责返回结果，不负责输出。

打印 `score`、`source`、`chunk index`、`preview` 应该放到 CLI 或 demo 层。这样 `internal/rag` 更容易测试，也更适合后续被不同入口复用。

## 今日核心理解

内存向量搜索本质上是在做：

```text
用户问题向量
  和每个 chunk 向量计算相似度
  挑出分数最高的 topK 个 chunk
```

RAG 的回答质量很依赖这一步。如果检索出的 chunk 不相关，后面 prompt 写得再好，模型也很难给出可靠答案。

今天最重要的理解是：

```text
embedding 负责把文本变成向量
cosine similarity 负责判断两个向量是否相近
topK 负责限制进入 prompt 的上下文数量
```
