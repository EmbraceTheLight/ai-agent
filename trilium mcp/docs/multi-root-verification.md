# 多目录与目录锁验证

日期：2026-11-24。MCP 服务版本：0.2.0。工具链：Go 1.26.8，Windows amd64。

实现兼容原来的单 ID 配置，并支持 JSON 数组、排序去重、嵌套目录合并、跨进程顶层目录锁和操作 ID 锁。没有修改真实 `.env`、Codex 配置或运行中的可执行文件。

新增测试验证：

- 单 ID、数组、重复和顺序、非法数组项及 root 拒绝。
- 多层嵌套合并；兄弟目录不提升到未配置的共同祖先；移动后重新解析。
- 祖先循环、缺失、受保护配置项及范围外克隆拒绝。
- 一个目录持锁时，另一个目录中的完整追加操作仍可成功。
- 两个独立进程之间同目录互斥，不同目录可取得锁；等待可取消，释放后可继续。
- 跨目录克隆同时需要两把目录锁，未取得全部锁时释放已取得的锁。
- 操作 ID 独立互斥；已合并为同一单目录的数组配置可重放旧记录。
- 持锁后增加另一个目录的克隆路径时停止；待核对删除遇到祖先 404 时不能误判目标已删除。
- MCP 协议返回合并前后目录列表；多目录省略新建父级或搜索祖先时报错，显式指定后可创建和删除。

原有快照、摘要冲突、响应丢失恢复及 stdio 子进程协议测试继续通过。模拟测试使用假 Token，不访问真实笔记库。

## 真实实例只读验证

通过新可执行文件的 stdio MCP 连接 TriliumNext 0.104.1，先用 API 精确查询确认唯一 `root/temp`。随后选择该目录内一个已有直接子笔记，以临时进程环境传入包含重复项的数组，未改写 `.env`。

输入去重后为 `["v2YidQTHkFIY", "zYNgSdXFYpPF"]`，`trilium_info` 返回合并结果 `["v2YidQTHkFIY"]`，旧单值字段也保持为该 ID。服务返回版本 0.2.0。此次没有创建、更新或删除笔记，也没有在真实实例制造并发竞争；目录锁竞争使用自动化测试验证。

使用前应停止旧版本写入进程，再切换新程序并重启服务。所有协作进程必须使用同一状态目录及相同写入配置；本地锁不约束人工编辑或其他客户端。配置、锁及恢复细节见 [MCP 说明](mcp-guide.md)。
