## 第五阶段：叶子笔记软删除（2026-10-27）

新增 `DELETE /etapi/notes/{noteId}` 客户端调用，要求 ETAPI 返回 204，并在随后读取笔记确认其不可访问。按 ETAPI 语义这是软删除；首版只接受写入范围内未受保护、单父级、无子笔记的 `text` 或 `code` 笔记，拒绝范围根及克隆笔记。删除前持久化元数据和正文快照，以操作 ID 处理结果不明确后的核对与重试。

使用 Go 1.26.2 在 Windows amd64 执行 `go test ./... -count=1 -timeout=90s`、`go vet ./...`、`go build ./...`，均通过。模拟测试覆盖 API 方法、路径及 204 响应，CLI 与 MCP 调用，范围和叶子条件拒绝，过期摘要、快照后修改、重复请求及响应丢失后的恢复。未对真实 Trilium 笔记执行删除。ETAPI 的树检查与删除不是原子操作；若其他客户端在最终检查后为目标添加子笔记，服务端仍可能级联删除该子树。
