# 学习与开发顺序

## 角色关系

```text
现成 AI 客户端 / 未来自己编写的 Go Agent
                  │ MCP
                  ▼
Go MCP 服务：工具定义、参数结构、结果和错误映射
                  │ 普通 Go 调用
                  ▼
笔记操作：范围检查、内容处理、备份、冲突检查
                  │ 普通 Go 调用
                  ▼
ETAPI 客户端：HTTP、认证、JSON、超时
                  │ HTTP
                  ▼
TriliumNext
```

Agent 根据用户要求和工具结果决定下一步；MCP 服务提供可以被调用的工具；ETAPI 是 Trilium 的外部接口。MCP 服务通常无需模型 API Key。

## 已完成：只读 API 与 CLI

已提供实例版本查询、搜索、元数据读取、正文读取和本地模拟测试。

已与本机 TriliumNext 0.104.1 完成 `info`、`search`、`read` 联调，真实 URL 为 `http://127.0.0.1:37840`。Token 仅保存在本机 `.env`，不写入文档。

值得理解的三个问题：

- `http.Client.Timeout` 与 `context.Context` 各解决什么问题？
- 为什么 HTTP 401/404 和“连接失败”需要不同的处理方式？
- 为什么普通富文本笔记的正文含 HTML，而不是 Markdown？

这些问题用于结合代码阅读，不需要先写出完整答案才能继续开发。

## 已完成：可靠写入

在专用测试笔记子树中完成新建、追加及正文更新，重命名保留为后续独立功能。业务逻辑放在 `internal/notes`，命令行只负责输入输出。

已实现创建、追加、整篇正文替换、唯一 HTML 片段替换、Markdown 转 HTML、写入范围检查、修改前快照、内容摘要比对、写后核对及操作 ID 重试识别。更新和追加复用同一控制流程，原有操作记录格式保持兼容。使用方法见 `write-guide.md`，验证记录见 `verification.md`。以下约束持续适用：

1. `TRILIUM_WRITE_ROOT_ID` 限制 CLI 的写入范围；读取和搜索暂时保留原有范围。后续 MCP 若需要限制可读数据，必须再增加对应检查，不能把 Token 权限假定为已经限制到某个子树。
2. 根据 noteId 和父级路径理解克隆笔记；修改同一笔记会影响多个展示位置。
3. 保存原始内容和元数据；备份包含私有信息，路径与保留策略必须明确。
4. 读取和写入前的内容指纹比对。若实际 API 没有条件写入，必须承认其非原子性，不能承诺完全避免并发覆盖。
5. 写入后核对结果。创建或追加遇到超时不能盲目重试，否则可能重复写入。

新增 Markdown 内容可以转成 HTML；已有内容尽量保留原始 HTML，避免破坏附件引用和内部链接。删除仅支持写入子树内的单父级叶子笔记；移动和批量改树暂不提供。

此层保持普通 Go 方法，由 CLI 与 MCP 共同调用。

## 已完成：MCP 服务

使用固定版本的官方 Go SDK v1.7.0 和 stdio，已注册版本/范围查询、搜索、读取、列出子笔记、新建、追加、更新及叶子笔记删除工具；复用已有笔记操作逻辑。使用方法见 `mcp-guide.md`。读取保留 CLI 的 Token 范围，搜索默认限定写入根；写入范围由业务层执行。

需要理解工具名称、描述、输入结构、返回结果，以及客户端如何发现和调用工具。stdio 的 stdout 用于协议消息，普通日志应写入 stderr。

入口位于 `cmd/trilium-mcp`，工具定义位于 `internal/mcpserver`。协议由 SDK 处理，未引入远程 HTTP 部署、OAuth 或数据库。可从内存传输协议测试入手，理解客户端和服务器两端如何衔接。

## 最后阶段：自己的 Go Agent

在学到 MCP 客户端后，用自己的 Go Agent 发现并调用同一个 MCP 服务，观察“用户要求 → 模型选择工具 → 执行 → 返回结果 → 下一次决策”的过程。

## 升级兼容

- ETAPI 细节集中在 `internal/trilium`；不直接读写 Trilium 数据库，不依赖内部 `/api/*`。
- 版本查询只用于诊断，不能单凭版本字符串推断所有能力。
- 保留响应结构和错误场景的测试；新增字段尽量兼容，必要字段变更明确报错。
- Trilium 升级后先查版本、搜索、读取；写入功能完成后，再在专用测试子树核对写入。
- 引入 MCP SDK 时固定依赖版本，升级时分别验证 SDK 和 Trilium，避免同时改变多个变量。

## 协作方式

每次推进一个能运行和验证的小目标。解释关键路径、提供代码评审或按委托实现；不要求为了学习重复抄写机械代码，也不一次铺开完整 Agent 框架。
